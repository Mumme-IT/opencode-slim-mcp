# 1.0.0 — Native OpenCode V2 CLI and skills

This is a breaking, V2-only release. It requires **OpenCode 2.0.23** and **Node.js 24 or newer**. It contains no V1 runtime or dual-version entrypoint.

## Changes

- Map explicitly selected native MCP tools to the `slim-mcp` CLI and compact, on-demand skills.
- Keep native OpenCode transports, OAuth, connection state, permissions, and cancellation instead of creating a second MCP runtime.
- Provide JSON catalog, schema, status, and execution commands through public plugin RPC and `@opencode/client`.
- Bind execution to genuine foreground shell invocations and reject replayed, expired, cross-Location, and unsupported background/external requests.
- Preserve structured results with bounded output and private media/large-result artifacts.
- Remove the old proxy tool, generator, credential-file reader, V1 hooks, and V1 sidebar. The optional sidebar is not included in this release.

## Migration

Move `slim: true` selections into `options.servers` and explicitly set `exclusiveNamespaces: true`. Keep native MCP definitions enabled under `mcp.servers`. Install the CLI on the OpenCode server host. Use the new skills and `slim-mcp` commands instead of the old proxy or generated wrappers.

Remove obsolete generated artifacts only after verifying ownership. Do not remove native credentials or shared skill/state directories. See the README for complete installation and migration instructions.

## Verification

Typechecking, nine unit tests, builds, export/bin smoke tests, and an installed OpenCode 2.0.23 integration test with 42 assertions pass. The integration test installs a fresh package tarball and uses isolated local model/MCP fixtures. It covers native permissions, pending-approval configuration replacement, cancellation, result limits, and Location isolation.

## Explicitly accepted limitations

The user explicitly approves this stable release with these limitations:

- A live MCP catalog change can precede revocation while a call waits for approval. Atomic catalog identity at native execution requires an upstream interface.
- Native executors collapse several error categories and do not reproduce separate outer MCP dispatch hooks or history rows.
- Selected namespaces must remain exclusive to their native MCP servers.
- Remote OAuth/account changes and broader deployment/cancellation cases remain unverified.
- Net token savings over native V2 Code Mode are not established. Small catalogs can cost more through CLI discovery and skill loading.

Publication does not claim those requirements are validated. See `docs/implementation.md` for the evidence and remaining validation work.
